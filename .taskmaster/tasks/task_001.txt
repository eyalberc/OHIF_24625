## Integration Issue Analysis: StudyService Dependency

### Critical Integration Problem Identified
The GlobalPatientHeader component incorrectly attempts to access `servicesManager.services.StudyService`, which does not exist in OHIF v3 architecture. This is causing a fundamental data access failure.

### Architectural Mismatch
- **Current Implementation:** Relies on non-existent StudyService
- **OHIF v3 Architecture:** Uses DicomMetadataStore and DisplaySetService for patient/study data

### Correct Implementation Pattern
Patient and study data should be accessed through:
1. DicomMetadataStore for study metadata and patient information
2. DisplaySetService for display set management when needed

### Data Access Pattern
The component should:
- Query DicomMetadataStore for study instance UIDs
- Access study metadata through DicomMetadataStore methods
- Subscribe to DicomMetadataStore events for updates

### Available Study Properties
Key properties available through DicomMetadataStore include StudyInstanceUID, PatientName, PatientID, StudyDate, StudyDescription, AccessionNumber, ModalitiesInStudy, and NumInstances.

### Impact Assessment
- **Severity:** HIGH - Component cannot access patient data
- **Function:** Component likely displays "No Patient Selected" consistently
- **Fix Required:** Complete rewrite of data access logic
- **Dependencies:** None - can be addressed immediately
